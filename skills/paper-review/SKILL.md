# 논문 리뷰 조율

목표는 요약 분량이 아니라 독자가 문제·방법·근거·한계를 설명하고 다른 연구와 비교할 수 있게 하는 것이다. 사용자 언어로 작성한다. 분야 초보자에게 필요한 설명과 정확성을 함께 유지한다.

## 범위와 라우팅

입력에서 연구 질문, 논문/PDF/DOI, 독자 수준, 깊이, 결과물 위치를 추출한다. 없으면 해당 분야는 처음 접하지만 기본 AI 개념은 아는 독자로 가정한다. 코딩 숙련도와 분야 지식을 동일시하지 않는다. 합리적인 기본값으로 진행하되 핵심 자료가 없으면 필요한 부분만 요청한다.

항상 [공통 근거 기록](references/evidence-contract.md)을 읽고, 아래에서 필요한 세부 스킬만 읽는다. 이 구조는 지침 라우팅이며 자동 도구 실행·하위 에이전트 생성이 아니다.

| 요청 | 읽을 지침 |
|---|---|
| 핵심만 파악 | [paper-explain](../paper-explain/SKILL.md) + 핵심 주장 원문 대조 |
| 분야 탐색·선행/후속 논문 | [literature-map](../literature-map/SKILL.md) |
| 수식·방법 정독 | [paper-explain](../paper-explain/SKILL.md), 필요하면 [evidence-check](../evidence-check/SKILL.md) |
| 성능 주장·실험 타당성 검토 | [evidence-check](../evidence-check/SKILL.md) |
| 여러 논문 비교·연구 아이디어 | [research-connect](../research-connect/SKILL.md), 빠진 근거는 위 단계로 보충 |
| 전체 리뷰 | 필요한 탐색 → 이해 → 검증 → 연결·확장 순으로 수행 |

세부 스킬은 이 묶음과 함께 설치한다. 누락되면 수행하지 않은 단계를 완료라고 하지 말고, 사용 가능한 범위에서 진행한다. 일상적인 한 질문에 전체 절차를 강제하지 않는다.

## 수행 원칙

- 논문 버전과 실제 접근 범위를 먼저 확인한다. 초록만 있으면 초록 기반 리뷰로 축소한다.
- Deep Research는 제공되는 경우 조사 도구로 사용한다. 없으면 일반 검색·공식 저장소·제공된 자료로 수행하고 사용하지 않은 제품을 사용했다고 쓰지 않는다.
- Google Scholar는 사용 가능한 정상 접근으로 참고문헌·인용 논문을 조사한다. 차단·로그인·캡차는 우회하지 않고 공개 서지 서비스나 제공 목록으로 보완한다. 완전한 체계적 문헌고찰이라고 주장하지 않는다.
- 비공개 원고·환자 정보·내부 연구 아이디어를 외부 검색어나 공개 원고에 넣지 않는다. 검색에는 공개 서지 정보와 일반 용어만 사용한다.
- 모르는 내용을 채워 넣는 대신 주장별 근거 위치와 미확인 사항을 남긴다. 과학적 타당성과 재현 여부를 구분한다.
- 코드·시각화는 이해에 필요한 경우만 만든다. 실행하지 않은 코드는 실행 결과처럼 제시하지 않는다.

## 결과물

[리뷰 양식](assets/review-template.md)을 참고하되 필요 없는 절은 생략한다. 빠른 읽기는 핵심·근거·한계만, 정독은 수식과 실험까지, 비교는 관계와 차이를 중심으로 쓴다. 같은 내용을 도입·표·마무리에 반복하지 않는다.

원문에서 확인한 내용 / 리뷰어 해석 / 제안한 가설을 시각적으로 구분한다. 관계도 화살표에는 관계와 근거를 붙인다. 초보자 설명의 기준은 [설명 원칙](references/explanation.md)을 따른다.

파일 저장 요청이 있으면 새 초안 또는 사용자가 지정한 노트에 저장한다. 기존 볼트 전체를 임의로 재구성하거나 게시하지 않는다. 기존 note-review가 명시적으로 제공되면 마지막 기록 검토에 재사용할 수 있으나 필수 의존성은 아니다. paper-review-site는 웹 결과물이 요청된 경우에만 이어서 사용한다.

저장 형식 선택, HTML·슬라이드 출력, 긴 작업의 상태 기록이 필요하면 [출력과 재개](references/output-and-resume.md)를 읽는다. 이미 지정된 형식·위치·공개 범위는 다시 확인하지 않는다. 이 참조는 운영 지침이며 실행 훅이나 렌더러가 설치됐다는 뜻은 아니다.

## 완료 점검

로컬 실행 코드는 [도구 연결](references/toolkit.md)을 따른다. 공통 데이터 구조와 명령 사용법은 저장소 README.md에 있다. 지침 검증·코드 테스트·원문 검토를 구분한다.

독자가 문제와 핵심 방법을 설명할 수 있는가? 주요 주장에 실제 근거가 있는가? 그림·수식의 가정이 보존됐는가? 논문 사이 관계가 확인과 추론으로 나뉘었는가? 확장 아이디어에 검증 조건이 있는가? 접근·실행하지 않은 범위가 표시됐는가?
