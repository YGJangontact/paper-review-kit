# AI 논문 리뷰, 요약에서 끝내지 않으려고 스킬과 검증 도구를 만들었어요

논문을 AI에게 요약해 달라고 하면 읽는 속도는 빨라져요. 그런데 며칠 뒤 다시 보면 다른 질문이 생깁니다. 이 설명은 원문에 있었을까? 수식은 정말 이해했을까? 다른 논문과 연결한 부분은 저자의 주장일까, 제 생각일까?

그래서 이번에는 논문을 읽는 순서를 재사용할 수 있는 스킬로 만들고, 기록을 검사하는 Python 도구까지 붙여봤어요. 공개된 LoRA 논문으로 자료 추출부터 근거 기록, 수식 확인, 웹페이지와 슬라이드 출력까지 한 번 이어서 실행했습니다.

**이 글에서 볼 내용**

01. 논문 리뷰를 다섯 역할로 나누기
02. 설명과 근거를 함께 남기는 방법
03. LoRA로 실제 확인한 것과 확인하지 않은 것
04. 원하는 형태로 저장하고 이어서 작업하기

## 01. 하나의 입구, 필요한 역할만 불러오기

스킬은 AI에게 반복해서 설명하던 작업 순서를 파일로 정리한 것이에요. 이번 구성은 `paper-review`가 전체 순서를 안내하고, 필요한 세부 스킬을 참조하는 방식입니다. 여러 AI가 자동으로 동시에 실행된다는 뜻은 아니에요.

| 스킬 | 맡긴 역할 |
|---|---|
| paper-review | 질문·읽기 범위·검토 순서·결과물 관리 |
| paper-explain | 배경부터 수식과 그림까지 단계적으로 설명 |
| evidence-check | 주장과 원문 위치·실험 조건 대조 |
| literature-map | 선행·후속 연구와 인용 관계 정리 |
| research-connect | 논문 간 차이와 확장 아이디어 구분 |

처음 보는 논문이라면 문제와 용어부터 시작해요. 그다음 작은 예시, 수식, 실험 조건 순서로 깊이를 늘립니다. 이미 아는 부분은 줄이고 어려운 수식만 자세히 설명하도록 요청할 수도 있어요.

## 02. 이해한 설명 옆에 근거를 남겼어요

리뷰에는 세 가지를 구분합니다. **원문에서 확인한 사실**, 그 사실에 대한 **제 해석**, 아직 검증하지 않은 **확장 가설**이에요. 문장마다 관련 출처와 페이지·절·수식 위치를 붙여 다시 찾아갈 수 있게 했습니다.

관련 연구를 넓게 찾을 때는 Deep Research로 후보를 모으거나 Google Scholar에서 참고문헌과 후속 인용을 따라갈 수 있어요. 다만 이번 검증에서 이 두 서비스를 실행한 것은 아닙니다. 찾은 후보의 원문 접근 범위와 실제 읽은 부분을 남기는 절차를 스킬에 정리했어요. 인용되었다는 사실만으로 성능이 검증되었다고 쓰지 않습니다.

Python 도구는 PDF 텍스트 추출, 출처 ID와 필수 항목 검사, DOI 중복 후보 확인, 결과물 출력과 변경 감지를 맡아요. **검사 통과가 논문의 주장이 참이라는 뜻은 아닙니다.** 일부러 틀린 주장도 형식이 맞으면 구조 검사를 통과하는 테스트를 넣어 이 한계를 확인했어요. 내용은 원문과 직접 대조해야 합니다.

## 03. LoRA 공개 논문으로 끝까지 실행해봤어요

LoRA는 기존 가중치를 고정하고 작은 두 행렬을 학습해 변화량을 표현하는 방법이에요. 초보자용 설명에서는 먼저 ‘큰 표를 전부 고치기보다 작은 보정값을 더한다’는 그림으로 시작하고, 그다음 행렬 곱으로 연결했습니다.

이번에는 LoRA v2 PDF 26쪽에서 텍스트를 추출하고, 핵심 방법이 나오는 인쇄 페이지 4~5쪽을 그림으로도 확인했어요. 수식의 배율, 가중치 병합, 원래 모델 가중치를 계속 보관한다는 설명을 대조했습니다. QLoRA는 초록만 읽었으므로 관계 소개도 그 범위로 제한했어요.

<!-- IMAGE: deck-content.png -->

*직접 만든 설명 슬라이드. 근거와 해석을 구분하고, 읽은 범위를 함께 표시했습니다.*

수식은 작은 숫자로 직접 계산했습니다. alpha를 0, 0.5, 1, 2로 바꾸는 네 경우에, 보정 경로를 따로 계산한 결과와 가중치에 합쳐 계산한 결과가 일치했어요. 브라우저에서는 슬라이더로 배율을 바꾸며 출력이 달라지는 모습을 볼 수 있습니다.

<!-- IMAGE: deck-demo.png -->

*직접 만든 수식 실험 화면. 작은 행렬의 계산 예시이며 실제 모델 학습 결과는 아닙니다.*

| 점검 항목 | 이번에 확인한 범위 |
|---|---|
| 코드 검사 | 자동 테스트 14개 통과 |
| 수식 확인 | 작은 행렬의 배율 4가지 계산·병합 결과 일치 |
| 결과물 | HTML 리뷰, 6장 슬라이드, Markdown, 관계도 생성 |
| 화면 확인 | 슬라이더 경계값·슬라이드 탐색·390px 폭 화면 확인 |
| 남은 한계 | 대규모 모델 학습·성능·GPU 속도 재현은 하지 않음 |

논문 전체의 모든 주장과 실험을 검증한 결과는 아니에요. 이번에 확인한 것은 **선택한 방법 설명을 읽고, 근거를 기록하고, 작은 수식 계산을 확인해 결과물로 만드는 작업 흐름**입니다. 검증 범위도 저장소에 함께 공개했습니다.

## 04. 정리는 Markdown, 설명은 웹페이지와 슬라이드로

항상 발표자료까지 만들 필요는 없겠죠. 간단한 기록은 Markdown으로, 개념을 직접 만져보며 설명할 때는 HTML과 인터랙티브 슬라이드로 정리하도록 나눴어요. 옵시디언용 Markdown과 논문 관계도도 선택해 내보낼 수 있습니다. 실제 옵시디언 앱 안에서의 화면 검증은 아직 하지 않았어요.

중간에 멈췄다가 돌아왔을 때는 저장된 파일의 변경 여부를 확인합니다. 입력이 바뀌면 이전 완료 표시를 오래된 상태로 표시해 다시 점검하도록 했어요. 세션 훅은 수동으로 실행하는 연결 어댑터까지 만들었고, 특정 제품의 세션 시작 이벤트에 자동 등록하지는 않았습니다.

요청은 이렇게 시작할 수 있어요.

> 이 논문을 처음 읽는 사람 기준으로 설명해줘. 문제 → 필요한 배경 → 작은 예시 → 핵심 수식 → 실험과 한계 순서로 정리하고, 원문 사실·내 해석·확장 가설을 구분해줘. 읽지 못한 출처는 확인한 것처럼 쓰지 말고, 관련 연구는 실제 인용 관계와 주제 유사성을 나눠줘. 우선 Markdown으로 정리하고, 핵심 수식만 인터랙티브 슬라이드로 만들어줘.

AI가 읽는 속도를 높여주는 만큼, 저는 **어디까지 확인했는지 다시 따라갈 수 있는 기록**을 남기려고 합니다. 요약을 많이 만드는 것보다 다음에 읽을 때 덜 헷갈리는 쪽으로요.
